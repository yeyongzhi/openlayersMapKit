# 核心模块覆盖率统计口径与阈值

> 建立日期：2026-09-03  
> 当前状态：已完成（2026-09-03）  
> 来源：核心 API 行为与生命周期审计的覆盖率统计口径例外

## 背景

当前 `vitest.config.ts` 排除了全部 `src/**/index.ts`，而 `Map`、`Popup`、`Control`、`Interaction`、`BaseLayer`、`Source`、`Event` 等核心包装对象的主体实现位于 `index.ts`。因此，现有 V8 覆盖率报告不能直接验证核心生命周期模块“行覆盖率不低于 85%、分支覆盖率不低于 75%”的目标。

本任务仅调整覆盖率统计和门禁，不改变公开 API 或业务契约。

## 执行任务

- [x] 盘点被 `src/**/index.ts` 排除规则隐藏的入口转发文件与主体实现文件。
- [x] 将纯导出入口与包含实现的 `index.ts` 区分处理，避免为无可执行逻辑的聚合导出制造覆盖率噪声。
- [x] 调整 Vitest 覆盖率 include/exclude，使核心包装对象主体进入统计。
- [x] 保存调整后的全仓和核心模块覆盖率基线，并说明与旧口径不可直接比较的部分。
- [x] 核查现有生命周期契约测试是否覆盖创建、挂载、移除、重挂载、释放和重复释放路径。
- [x] 核查真实生命周期缺口；本轮未发现需新增的契约场景，不为提升数字编写无行为价值的断言。
- [x] 根据基线确认核心模块行 85% / 分支 75% 是否合理；如需分阶段达到，记录阶段阈值和原因。

## 执行报告

### 统计口径

覆盖率继续包含 `src/**/*.ts` 并排除类型文件，但不再排除全部 `index.ts`。仅排除以下无业务实现的聚合导出入口：

- `src/index.ts`
- `src/module/basic/index.ts`
- `src/module/control/index.ts`
- `src/module/core/index.ts`
- `src/module/core/Feature/index.ts`
- `src/module/interaction/index.ts`
- `src/module/layer/index.ts`
- `src/module/source/index.ts`
- `src/module/source/TileSource/subClass/index.ts`
- `src/module/util/index.ts`
- `src/utils/index.ts`

其余包含类、函数或运行时常量实现的 `index.ts` 均进入统计。

### 新口径基线与门禁

新口径全仓基线为：语句 60.05%、分支 46.94%、函数 61.07%、行 60.21%。旧口径排除了大量主体实现，行 78.40%、分支 61.28% 与新结果不可直接比较。

全仓门禁按新基线设置为行 60%、分支 46%。核心包装对象主体设置防回退阶段阈值：

| 主体          | 实测行覆盖率 | 实测分支覆盖率 | 阶段门禁（行/分支） |
| ------------- | -----------: | -------------: | ------------------: |
| `Popup`       |       74.46% |         58.13% |           74% / 58% |
| `Control`     |       54.00% |         22.22% |           54% / 22% |
| `Map`         |       55.13% |         42.85% |           55% / 42% |
| `Interaction` |       87.35% |         78.37% |           87% / 78% |
| `BaseLayer`   |       47.16% |         40.19% |           47% / 40% |
| `Source`      |       60.00% |         62.50% |           60% / 62% |
| `Event`       |       84.61% |         78.94% |           84% / 78% |

原定行 85% / 分支 75% 仍作为长期目标，但当前只有 `Interaction` 同时达到。直接将其设为所有核心对象的统一门禁会使现有基线无条件失败，因此先通过精确到主体文件的阶段阈值阻止回退；后续测试建设应优先处理 `Control`、`Map`、`BaseLayer`，并随覆盖率提升上调对应阈值。

### 测试核查

现有专项测试已覆盖核心生命周期的创建、挂载、移除、重挂载、释放、重复释放、Map 连带释放、Source 所有权、监听解绑和销毁后错误契约。新口径暴露的主要缺口是普通属性、查询、构造重载和非法输入分支，而不是缺少生命周期主路径。本轮未增加只为覆盖数字而重复既有契约的测试。

### 验收

- `pnpm test:coverage`：39 个测试文件、294 项测试通过，新口径全仓及核心主体阶段阈值通过。
- 最终验收以本轮末次 `pnpm check` 与 `pnpm audit:api` 输出为准。
