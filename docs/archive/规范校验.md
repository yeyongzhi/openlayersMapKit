### 阶段 D：统一核心承载值与下划线语义

优先级：P1  
风险：低到中  
状态：已完成

前导下划线统一表示：**包装对象的核心承载值（backing value）**。它是该类封装、代理或规范化后的主要底层表示，不限于 OL 原生实例。

典型示例：

```ts
private _map: OlMap
private _color: string
private _lngLat: OlCoordinateType
private _extent: OlExtentType
private _pixel: OlPixelType
private _size: OlSizeType
```

判定规则：

1. 去掉该字段后，对象将失去其主要被包装或表示的内容，该字段可以视为核心承载值。
2. 一个类通常只有一个核心承载值；确有组合封装需求时可以有多个，但必须能明确说明各自职责。
3. 核心承载值使用 `_xxx`，并必须声明为 `private` 或因继承需要声明为 `protected`。
4. 生命周期状态、配置、缓存、管理器、事件集合和派生数据不是核心承载值，不使用前导下划线，例如 `disposed`、`options`、`layerManager`、`events`。
5. 局部变量和内部方法不使用前导下划线；未使用的接口参数是唯一允许的局部命名例外。
6. 核心承载值不直接作为公开字段暴露，通过 `getMap()`、`getColor()`、`toArray()` 等方法访问。
7. 数组、对象等可变承载值对外返回时默认复制，避免调用方绕过类的校验逻辑修改内部状态。

命名要求：

- 使用字段所承载的领域对象命名，如 `_map`、`_color`、`_extent`。
- 不统一写成缺少语义的 `_value`，除非类本身确实是通用值容器。
- 缩写和大小写遵循项目标准，因此推荐 `_lngLat`，不继续新增 `_lnglat`。
- 如果类只是组合多个普通业务字段而没有单一承载值，不强行为其字段增加下划线。

建议执行顺序：

1. 局部变量。
2. 私有内部方法。
3. 普通状态字段。
4. 可能影响子类的 `protected` 字段。

- [x] 将 `_options` 改为 `options`、`resolvedOptions` 等名称。

验收标准：

#### 类注释标准

TypeScript 的 `class` 声明已经表达“这是一个类”，因此不再强制编写 `@class`。注释开头的摘要已经承担描述作用，不重复编写 `@classdesc`。

推荐模板：

```ts
/**
 * 表示经过规范化的颜色值。
 *
 * 支持十六进制、RGB、RGBA 和预设颜色名称；内部统一保存为可输出的颜色字符串。
 *
 * @example
 * const color = new Color('#000000')
 * color.toString()
 */
export class Color {}
```

仅在确有信息时增加：

- `@example`：非直观用法或主要入口示例。
- `@deprecated`：废弃原因、替代 API 和迁移方向。
- `@see`：关联的重要 API 或外部规范。
- `@throws`：调用者需要处理的稳定异常契约。
- `@remarks`：不能放进首段摘要的约束、性能或生命周期说明。

默认不再新增：

- `@class`：TypeScript 类声明可以直接推断。
- `@classdesc`：与注释首段描述重复。
- `@author`：由 Git 历史和代码所有权维护；多人修改后单一作者容易失真。
- `@version`：类级版本容易与 `package.json` 版本脱节。
- `@createDate` / `@updateDate`：不是统一标准标签，且手工日期容易过期；使用 Git 历史查询。

自动化建议：

1. 日常编辑优先使用 VS Code 内置 JSDoc 补全：在声明上方输入 `/**` 后回车。
2. 若需要对单文件、目录或工作区批量生成，可选用 VS Code `JSDoc Generator`；生成后仍需人工补充真正有价值的语义。
3. 持续校验使用 `eslint-plugin-jsdoc`，重点启用标签名称、参数名称、返回值、对齐和导出 API 注释要求。
4. 若希望 Codex 按统一标准批量补文档，可选装 `giuseppe-trisciuoglio/developer-kit@typescript-docs` 技能；安装前继续核查其规则是否与本项目模板一致。
